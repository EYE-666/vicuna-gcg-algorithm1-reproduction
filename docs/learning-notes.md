# 实验过程中学到的内容

这份记录总结了我在复现 Vicuna-7B 上的 GCG Algorithm 1 时遇到的关键问题，以及我从中得到的认识。它描述的是一次单模型、单行为实验，不代表对论文全部实验结果的完整复现。

## 1. 复现代码时需要记录实际依赖环境

上游项目声明的依赖包括 `fschat==0.2.20` 和 `transformers==4.28.1`，但我在当前 Python 3.8 和软件源环境中安装时遇到了版本解析与构建问题。最终成功运行实验的主要版本为：

```text
torch        2.0.0+cu118
transformers 4.31.0
tokenizers   0.13.3
fschat       0.2.23
```

我学到，复现实验不能只写“安装成功”，还应同时记录上游要求和实际使用的版本。当前结果证明这套兼容环境可以运行，但不能将其描述为对论文原始软件环境的完全复刻。

## 2. 模型下载也是复现实验的一部分

从 Hugging Face 下载 Vicuna-7B-v1.3 时，两个大型权重分片的速度只有几百 KB/s，下载预计需要数小时。后来我改用 ModelScope 上的 `Xorbits/vicuna-7b-v1.3` 镜像，下载速度约为 11 MB/s，最终模型目录约为 13 GB。

我学到，使用镜像可以解决网络速度问题，但下载后仍应检查模型名称、配置文件、权重分片是否完整，并记录实际模型来源，不能因为目录名称相同就默认内容一定一致。

## 3. 模型能加载不等于攻击算法能在同样显存中运行

Vicuna-7B-v1.3 加载后约占用 12.58 GB 显存，但 GCG 运行时还需要计算梯度，并同时评估一批候选 token。使用较大的默认候选批量时，32 GB 显存出现了 CUDA OutOfMemoryError。

本次实验只把数值参数 `batch_size` 调整为 `16`，没有修改 GCG 的核心算法逻辑，并完成了 500 步运行。我学到，估算显存时不能只看模型权重，还必须考虑梯度、中间激活和候选批量。减小 `batch_size` 可以降低峰值显存，但也会影响每一步评估的候选数量和实验效率，因此必须如实记录。

## 4. Demo 中的 `Passed=True` 可能是假阳性

在 Demo 中曾出现以下组合：

```text
Passed: True
Completion: </s>
```

这并不表示模型执行了目标请求。项目的 `Passed` 检查主要判断输出中是否出现预设的拒绝前缀；空输出或只有结束符的输出没有包含这些拒绝词，也可能被判定为 `True`。

我学到，不能只看一个布尔指标就宣布攻击成功，必须同时检查模型实际生成了什么。

## 5. Demo 跑通和正式运行 Algorithm 1 是两件事

Demo 更适合验证模型能否加载、梯度能否计算以及候选更新流程是否能够执行。正式实验则通过 `experiments/main.py` 运行并保存完整的参数、检查点、指标与日志。

本次正式实验运行了 500 步，最终记录为：

```text
Step 500/500
Passed 1/1
EM 1/1
Loss 0.0279
```

我学到，Demo 成功只能说明基本代码链路可用；要说明 Algorithm 1 已经完成一次正式实验，还需要固定配置、运行完整迭代并保留可核查的结果文件。

## 6. 判断攻击结果需要结合多项证据

Loss 下降表示目标字符串的优化方向取得进展，但 Loss 较低本身不等于最终生成命中了目标。`Passed` 只说明生成结果没有匹配预设拒绝前缀，也可能出现假阳性。`EM` 表示生成内容命中了设定的目标字符串，因此比单独的 `Passed` 更有说服力，但仍要人工查看生成文本。

本次实验同时保留了最佳控制后缀、Loss、`Passed`、`EM` 和测试生成内容。最终 `Passed 1/1`、`EM 1/1`，且生成文本出现了设定的肯定性目标前缀，因此可以说明这次单行为目标前缀优化成功。由于测试生成内容较短，这个结论不应扩大为“模型生成了完整的危险实现”，也不代表对其他行为或模型同样有效。
